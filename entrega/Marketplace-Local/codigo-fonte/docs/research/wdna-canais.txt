 21. Canais 
 Gerencia os canais de venda conectados à loja: a própria loja virtual, marketplaces (ex.: Mercado Livre), ERPs (ex.: Bling) e canais genéricos de API/teste. Cada canal tem sua própria tabela de preço, mapeamento de produtos e fluxo de pedidos.

 Configurar canal 
 Cada canal abre sua própria tela de configuração, específica do seu Tipo. Um canal de marketplace como o Mercado Livre, por exemplo, mostra abas de Dados gerais (nome, tabela de preço, credenciais do aplicativo e token de acesso, com um botão para renovar a autorização), Mapeamentos, Produtos, Estoque, Pedidos, Anúncios, Gestão, Perguntas/Chat e Contato/Notificações — outros tipos de canal mostram um conjunto de abas diferente e mais enxuto, de acordo com o que essa integração suporta.

 Tipo 
 Função

 Canais > Loja virtual 
 Canal Loja virtual — Dados gerais 
 O canal do tipo "Loja virtual" representa a própria vitrine da loja. A aba "Dados gerais" concentra os padrões do canal como um todo: tema, modo de exibição, tabela de preço/estoque/frete/pagamento padrão, selos, exibição de moeda, domínios, documentos aceitos, emissor de nota fiscal e regras de checkout.
 Canal "Loja virtual" — aba Dados gerais, metade superior: nome, tema, modo de exibição e padrões do canal 
 Canal "Loja virtual" — aba Dados gerais, metade inferior: valores em destaque, domínios, documentos, NFe e checkout 
 Elemento 
 Tipo 
 Função 
 Nome / Tema Texto / Seleção O nome de exibição do canal e qual tema de vitrine ele usa. 
 Modo de exibição Select B2C ou B2B — muda o comportamento de catálogo/checkout para compradores consumidores ou empresas. 
 Padrões do canal Tabela de preço, Estoque, Frete, Pagamento, Páginas adicionais, Códigos incorporados, Plugins Recursos padrão aplicados no canal como um todo, salvo substituição em outro ponto. 
 Selos Rede social / Pagamento / Outros Quais conjuntos de selos (de Personalizar > Coleção de selos) aparecem na vitrine para redes sociais, pagamento e outros selos de confiança. 
 Valores em destaque Símbolo de moeda / Destaque primário / secundário Símbolo de moeda exibido nos preços, e quais campos de preço (ex.: parcelamento, desconto PIX) são destacados na página do produto. 
 Domínios Lista Domínios personalizados apontados para este canal; um é marcado como padrão. 
 Documentos aceitos e ativação CPF/CNPJ + interruptor Quais tipos de documento os clientes podem usar no cadastro, e se novas contas são ativadas automaticamente. 
 NFe Emissor / interruptor de emissão automática Qual integração de emissão de nota fiscal é usada e se as notas são emitidas automaticamente por pedido. 
 Checkout Qtd. mín. de produtos, seleção de vendedor, regras de documento/senha Tamanho mínimo do carrinho, se o cliente escolhe um vendedor, se documentos aceitos são exigidos no checkout, e se uma senha é criada automaticamente no cadastro.

 Canais > Api 
 Canal Api 
 Um tipo de canal genérico para conectar sistemas externos diretamente pela API própria da WDNA, usando credenciais OAuth2 (client credentials) em vez de uma integração pronta de marketplace/ERP. Útil para integrações sob medida ou testes.
 Tela de configuração do canal Api: Client ID e Client Secret (mascarados aqui), com link para a documentação da API WDNA 
 Elemento 
 Tipo 
 Função 
 Observações Painel de informação Link para a documentação externa da API WDNA, para quem vai construir a integração. 
 Nome Texto O nome de exibição do canal. 
 Client ID / Client Secret Texto (somente leitura) As credenciais OAuth2 emitidas para este canal, usadas para autenticar as requisições à API. 
 Renovar credenciais Botão Revoga o Client Secret atual e emite um novo — qualquer integração usando o valor antigo para de funcionar imediatamente. 
 💡 A própria tradução da plataforma para inglês/espanhol nesta tela cai para chaves de campo não traduzidas (ex.: "Channel api client id") — isso é uma característica da plataforma ao vivo, não uma lacuna da documentação. 
 Canais > Bling 
 Canal Bling — Dados gerais e autorização 
 O canal Bling conecta a loja ao ERP Bling. A aba "Dados gerais" concentra as credenciais do aplicativo OAuth2 e o botão que inicia o fluxo de autorização do Bling; o banner no topo leva às instruções de configuração do próprio Bling.
 Canal Bling — aba Dados gerais: API key, Client ID/Secret, "Autorizar aplicação" e a URL de redirecionamento OAuth 
 Elemento 
 Tipo 
 Função 
 Banner de informação Link "Para configurar a integração clique aqui" — abre a tela de cadastro de aplicativo do próprio Bling em uma nova aba. 
 Nome / API key Texto O nome de exibição do canal e a API key gerada do lado do Bling. 
 Client ID / Client Secret Texto As credenciais do aplicativo OAuth2 criadas no painel de desenvolvedor do Bling para esta integração. 
 Autorizar aplicação Botão Inicia o fluxo de consentimento OAuth2 do lado do Bling para vincular as duas contas. 
 URL de redirecionamento OAuth Texto (copiar) A URL de callback para colar no cadastro do aplicativo no Bling, para que ele devolva o controle após a autorização. 
 Canais > Bling 
 Canal Bling — Módulos de sincronização 
 Além de Dados gerais, o canal Bling tem cinco abas de módulo de sincronização (Produtos, Estoque, Pedidos, Categorias, Clientes) mais uma aba Contato/Notificações idêntica à do canal loja virtual. Cada módulo de sincronização segue o mesmo padrão: um interruptor de Status (Habilitado/Desabilitado) e, no caso de Estoque e Pedidos, uma URL de retorno que precisa ser cadastrada do lado do Bling para que esses dados voltem para a loja.
 Aba Produtos: Status, identificador do produto (SKU/GTIN) e a lista de produtos sincronizados 
 Aba Estoque: aviso de URL de retorno, Status, saldo de estoque e as caixas de mapear estoques/estoque negativo 
 Aba Pedidos: aviso de URL de retorno (JSON urlencoded), Status e a lista de pedidos sincronizados 
 Elemento 
 Tipo 
 Função 
 Produtos Status + Identificador do produto Habilita a sincronização de produtos e define se o casamento é feito por SKU ou outro identificador; mostra a lista de produtos sincronizados. 
 Estoque Status + Saldo de estoque Habilita a sincronização de estoque; "Mapear estoques" vincula depósitos específicos, e "Permitir estoque negativo" deixa o saldo ficar abaixo de zero. 
 Pedidos Status Habilita a sincronização de pedidos com o Bling; exige que a URL de retorno seja cadastrada do lado do Bling com o tipo de callback "JSON (urlencoded)". 
 Categorias Status Habilita a sincronização de categorias entre a loja e o Bling. 
 Clientes Status Habilita a sincronização de clientes entre a loja e o Bling. 
 Contato/Notificações Igual ao da loja virtual Formulário idêntico ao da aba Contato/Notificações do canal loja virtual (ver acima): endereço, e-mail para cópia de notificações e a tabela de modelos de e-mail.
